Added

- `global.datapath` selects `ebpf`, `tproxy` or `auto` (default). The new netfilter TPROXY datapath intercepts LAN and host traffic with iptables `mangle` rules and fwmark policy routing on kernels the eBPF datapath cannot load (verified down to Linux 4.14), routing every flow in userspace; `auto` falls back to it with a warning.
- Android builds (`just build-android`, aarch64 and x86_64) for rooted devices: TPROXY is always selected, the default bypass mark becomes `0x400000` so honk's sockets stay routable under netd, state lives in `/data/adb/honk`, and `process_name` rules match the owning process of host-originated flows.
- The eBPF datapath loads on Linux 5.15 and newer (previously 6.12). Before Linux 6.6 interfaces are bound through `clsact` direct-action filters instead of TCX links; before 5.19 UDP DNS route marks are published in a map keyed by tuple and DNS transaction ID for the listener, which cannot read `SO_RCVMARK`; receive tracing follows each kernel's UDP receive-function arguments (with `noblock` before 5.19, without `addr_len` on recent kernels); and the NFQUEUE nftables transaction no longer waits for the batch-end acknowledgement that kernels before 6.10 never send. Older kernels select the TPROXY datapath under `datapath: auto`.

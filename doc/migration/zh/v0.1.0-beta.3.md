# 迁移到 v0.1.0-beta.3

适用于从 `v0.1.0-beta.2` 升级，仅列出影响已有配置或运维预期的变更。
各版本的迁移说明与本文件并列存放。

## 1. 升级前必读

| 变更 | 处理方式 |
| --- | --- |
| `lan_interface` / `wan_interface` 中的父设备（如 `eth1`）现在会跳过仍带 VLAN 标签且 VID 非零的帧，因此针对该子网写的 direct 与 block 规则不再对其生效，且不会有任何日志或报告。VID 0 优先级标签不变。 | 要管理该子网，须列出 VLAN 设备（`eth1.20`；VLAN-aware bridge 请列出 `br0.N`）。否则该子网按原生路径转发或应答。 |
| `lan_interface` / `wan_interface` 中的 `auto` 现在还会匹配大写、带空白和仅含空白的条目（例如带引号的 `" "`）。 | 删除并非有意指向默认路由网卡的写法。 |
| 网卡存在即绑定，不再要求 `IFF_UP`。 | 无需操作。 |
| 配置的 `vrf` 或 `openvswitch` master 的成员绑定在其自身，不再提升为 master。其他 master（`bond`、`bridge`、`team` 等）的成员仍解析为该 master。 | 请直接写出要拦截的网卡。 |
| `lan_interface` / `wan_interface` 中不支持的 bond/bridge 嵌套或自身即 master 的条目以 `unsupported_type` 被拒绝；其他配置项仍在启动时绑定并正常协调，不再以没有任何已配置 hook 的 `pending` 状态启动或在协调时冻结全部绑定。 | 写出受支持的根网卡，或拉平嵌套；即使 `lifecycle.state` 为 `running`，也要监控 `interface_binding`。见[接口挂钩集合](../../zh/design/datapath.md#接口挂钩集合)。 |
| LAN 与 WAN 角色按网卡各自确定：同时出现在两个列表中的名称是 LAN/WAN 共用网卡，不再让其他 LAN 网卡丢失反向 hook。 | 无需操作。 |
| `lo`、`vcan`、InfiniBand、非点对点 GRE、直接配置的 `vrf`、`dae0` 与 `dae0peer` 现在以 `unsupported_type` 被拒绝，不再挂载会按错误偏移解析的程序。启动仍会继续。 | 替换该条目（`vrf` 请改配其成员）。 |
| 网卡不存在、`auto` 未解析、类型被拒绝或 TCX 挂载失败，不再导致启动失败。该项不绑定任何 hook（或只绑定部分 hook），`GET /runtime` 报告 `interface_binding` 降级，而 `lifecycle.state` 仍为 `running`。位于尚不存在的网卡上的 `dns.bind` 仍会使启动失败。 | 对 `interface_binding` 降级告警；`running` 并不表示所有已配置网卡都已被拦截。 |
| bond 只在逻辑 master 上挂载 honk hook，配置中写出的成员名称解析为 master。LAN 角色的 bond 不再在成员上挂载 `wan_egress`，因此从 LAN bond 发出的网关本机流量不再被归为 WAN；master 与 bridge 端口一样携带 `lan_egress`。直接向成员注入的原始 `AF_PACKET` 帧，以及用 `SO_BINDTODEVICE` 绑定到成员的套接字所发流量，都不被拦截。 | 若依赖从 LAN bond 发出的网关本机流量被归为 WAN，请核对；此类套接字请绑定到 bond 而不是成员。 |
| 排在 honk 之后的第三方 TCX 程序，以及同一设备上的 legacy `clsact`/`cls_bpf` 过滤器，现在会看到 VID 非零的带标签帧，以及尚未分类的非 IP 或不支持的 L4 帧。列在 `lan_interface` 中的 `macsec0` 等上层设备上的流量现在会被分类。 | honk 自身无需操作。 |

## Netstack and WireGuard

Read with: `AGENTS.md` (Notes for agents: the netstack paragraph); `test-locations.md` for suites; `doc/en/design/netstack.md` (mechanisms, limits) and `doc/en/design/outbound.md#wireguard-tunnel` (driver specification); `configuration.md` for node fields and identity.

### Layout

- `crates/honk-netstack/src/`: `stack.rs` (public API, `Config`, `Rx`, class rotation, DRR), `mode.rs` (`Mode`, `ExcludeSet`), `offload.rs` (`RxMeta`/`Csum`, `GsoRx`, `TxCaps`, `Transmit`/`GsoTx`/`TxCsum`), `accept.rs` (transparent passive open: `poll_accept`/`tcp_accept`/`tcp_complete`/`tcp_refuse`, half-open accounting, `MAX_DEFERRED`), `udp_t.rs` (transparent UDP, `udp_send_from` TX fragmentation, `udp_send_gso_from` USO, `udp_refuse`), `icmp_out.rs` (ICMP generation, suppression, `IcmpLimits`), `fragment.rs` (bounded reassembly, `FragmentLimits`), `flow.rs` (generation slab, RFC 6056 ports, RFC 6528 ISN, TIME_WAIT table), `timer.rs` (lazy min-heap and the bounded list of flows marked since the last flush), `udp.rs` (Endpoint UDP), `icmp.rs` (ICMP receive), `wire/` (codecs, fragments and checksum), `tcp/` (`mod`/`input`/`output` state machine and GRO/TSO; `passive` admission gate and keepalive; `ring` configurable chunks, pool, floors and commitment; `sent` per-wire-segment scoreboard; `sack`; `rack`, `recovery`, `prr`; `rtt`; `cc` + `cubic`; `pacing`). `fuzz_checks/` (feature `fuzz-checks`) holds the replayable fuzz properties (`packet`, `schedule`, `transparent`); `benches/stack.rs` and `tests/alloc_free.rs` the per-packet cost and zero-allocation check; `tests/idle_footprint.rs` the idle per-flow heap and `tests/shared_budget.rs` the process budget. `lib.rs` documents the driving contract; keep it true.
- `crates/honk-outbound/src/proxy/wireguard/`: `mod.rs` handler, `registry.rs` per-plane tunnel registry and `TunnelConfig`, `tunnel.rs` shared state and owner task, `socket.rs` marked outer UDP with GRO/GSO, `stream.rs` TCP `FlowIo` and dial, `udp.rs` shared-source UDP. `runtime/wireguard.rs` is the per-runtime slot (it holds its plane's registry); `descriptor.rs` registers the protocol.
- Config side: `honk-config/src/node/wireguard.rs`, `share_link/wireguard.rs`, and the Clash/sing-box mappings in `honk-core/src/subscription/`; they follow `configuration.md`.
- `honk-datapath/src/{scope,buffer}.rs`: nonwrapping scope identities and fixed backend-frame ownership. Core `control/netstack{,/stream}.rs` owns the explicit packet Stack/stream/output runtime; `control/packet_endpoint.rs` joins it with existing TCP/UDP routing and outbounds. No daemon capture backend is published by these APIs.

### Stack invariants

- Sans-I/O: `forbid(unsafe_code)`; dependencies are `blake3` and `thiserror` only (`smoltcp` is a dev-dependency pinned to `=0.14.0` so the baseline keeps measuring the same code). The crate reads no clock, environment or file; time arrives as `Instant` arguments and the secret and limits in `Config`.
- One owner, `&mut Stack`. Every pending output is flow state; no unbounded or silently lossy queue. The only dropping queues are bounded and counted: control replies (128, `control_dropped`) and the OOO range table (32 ranges, `ooo_drops`); in transparent mode also the reassembly table (`FragmentLimits`, silent oldest eviction) and the Time Exceeded queue (16). A caller that stops pulling `poll_transmit` loses nothing.
- Every call that can create a send obligation (`tcp_write`/`shutdown`/`close`/`abort`/`connect`, a `tcp_read` that makes a window update due) must set `tx_wakeup`; the driver wakes its owner on `take_tx_wakeup()`.
- All `receive` calls of a batch use the same `now`. RTT, RACK and autotuning must not see processing time.
- `receive` verifies RX checksums in every mode (`RxMeta::VERIFY`). Only transparent `receive_with` may trust a local-device driver's `Csum::Valid`/`Partial`; Endpoint rejects any non-VERIFY metadata as `Unsupported`, so WireGuard can never select it. A `Partial` must point at the actual TCP/UDP checksum field or is `Malformed`; IPv4 headers, ICMP and reassembled datagrams are always verified. Full TX output copies the payload and computes its checksum with native-endian accumulation lanes; offloaded output is `TxCsum::Partial`, which the device/kernel must complete.
- Memory: every admitted TCP flow owns a floor (one TX chunk, one RX chunk, 16 descriptor slots) charged at admission; the remainder is the shared pool. A receive window is advertised only after it has been committed; the highest advertised right edge is never withdrawn and wire rounding goes down only. Accounting is by capacity, not logical bytes. The floor is not total accepted/idle commitment: `rcv_target` starts at `min(65535, clamped tcp_rcv_buf_max)`, and `tcp_accept` (including deferred) commits it beyond the floor as space permits. Empty rings return payload chunks, not the backing of an advertised window; an idle `Sent` releases descriptor storage. TCP floor/shared charges use `ring.rs`'s `Pool`, at active or passive admission, refunded on retirement/drop; `fragment.rs` separately charges reassembly to `Config::shared_budget`. Do not add TCP allocation paths that bypass `Pool`, and do not size the budget by floor alone.
- Counters (`packets_out`, `sacked`, `lost`, `retrans`) are incremental; `Sent::check` recounts them (and checks descriptor order, cursors and the remembered SACK runs) in debug builds and must keep running after every method that mutates the scoreboard; `Stack::check` (feature `fuzz-checks`) recounts the flow table, timers and queues.
- Fixed point only in congestion control (`cubic.rs`); do not introduce floating point.
- ICMP is consumed in every mode only for an outstanding quoted TCP sequence. In `Mode::Endpoint` it is never generated and fragments are dropped; only `Mode::Transparent` reassembles and generates. Changing the Endpoint behavior is a design change, not a fix.
- RTO floor 200 ms is intentional (shared with Linux; TLP covers it). Timestamps, SACK and window scaling are always offered.
- Modes: `Mode::Endpoint` is the default and the only mode the WireGuard driver uses (it never names `Mode`). Transparent behavior must not leak into it: no passive open (`tests/transparent_tcp.rs::endpoint_mode_has_no_passive_open`), `NotForUs` for non-local destinations, fragments dropped. In `Mode::Transparent` the local end of a flow is the packet's original destination and replies are sourced from it; `ExcludeSet` is only a backstop (the TC classifier is the gate); multicast, broadcast and unspecified destinations are dropped as `Unsupported`.
- Admission: a SYN creates a gated flow that emits nothing and ignores all input (retransmitted SYNs absorbed) until `tcp_accept`; an undecided SYN and a deferred accept die within `MAX_DEFERRED` (25 s, below the classifier's 30 s handoff; never raise it). Half-open caps (`half_open_max` 1024, `half_open_per_source` 128) and flow/floor/budget limits drop the SYN (`HalfOpen`/`Capacity`) and never RST or ICMP; no SYN cookies.
- Close: the active closer (simultaneous close included) keeps the compact 60 s TIME_WAIT with the RFC 6191 reopen check; the passive closer goes LAST_ACK to CLOSED. Server-side TIME_WAIT is never skipped, and any delivery state in front of the stack (eBPF entry, driver flow table) must outlive TIME_WAIT or a late FIN misses the tombstone and reaches the real server.
- In both Endpoint and Transparent mode, retained and compact TIME_WAIT ACK a validated duplicate data segment wholly before the consumed FIN, without redelivering data or updating expiry/`ts_recent` on receipt. Bare ACKs stay silent. A pending ACK at expiry retains the existing output-preserving timer re-arm; the driver must drain output.
- `tcp_retained(id)` queries the original Stack-local TCP handle through app close, compact TIME_WAIT and queued flow-owned refusals. `Transmit::flow` preserves that original handle even when the pull removes/compacts the TCB. Register returned output's in-flight ownership before consulting retention; false is not device/producer/task completion or a scoped retirement proof. Generation 0 is internal exhaustion, never issued to an application or returned to the free list; exhausted TIME_WAIT still runs to protocol completion.
- `new_accounted(cfg, now, max_slots)` requires one supplied shared budget, reserves metadata/cache/reallocation capacity before construction and bounds all slab slots, including TIME_WAIT/exhausted ones. `overhead_reserved()` is a conservative reservation, not RSS. Ring indices and RACK FIFO capacity remain funded through actual retained capacity. Ordinary construction/WireGuard defaults stay unchanged. Closing `set_accepting(false)` denies new passive opens, not existing protocol progress.
- `poll_control_transmit` shares the TCP emitter but forbids TCP/UDP payload; its lazy ready queue/class cursor must not rotate ordinary readiness, change DRR credit or consume payload TLP obligations. Reserve control or bulk frame/descriptor credit before pulling, offer both classes for progress, and retain materialized output until actual submission/disposal/return. Ordinary/WireGuard callers allocate no control-only queue.
- Reassembly completion reserves the destination while source storage is still charged. `OwnedPacket` owns its charge until the final byte owner drops, even after Stack destruction; capacity refusal is packet-local. Never detach an uncharged raw Vec or refund a retained completion clone.
- Reassembly (transparent): `FragmentLimits` defaults 64 entries, 4 MiB (retained data/header/range capacities plus fixed 256 B per entry), 32 holes, 30 s from the first fragment; overlap kills the datagram into a tombstone, the oldest datagram is evicted at the limits, Time Exceeded is queued only if fragment 0 arrived. Its bytes are charged to `Config::shared_budget` in `fragment.rs` (`grow`/`shrink`) and refunded on completion, eviction, timeout, kill and drop: a refused charge evicts the oldest, then drops (`Capacity` on entry admission, `Fragment` when the last datagram cannot grow). A fragment flood can therefore hold up to `max_bytes` of the budget; size the budget for it.
- ICMP generation (transparent): `IcmpLimits` defaults 1000/s, burst 50, per target 1 per 1 s with burst 6, 128 targets; suppressed for non-first fragments, special addresses and ICMP errors; whole error at most 576 B (IPv4) / 1280 B (IPv6); IPv4 admin-prohibited is 3/13, IPv6 is 1/1; packet-too-big is exempt from the rate limits. A too-small output buffer must leave every limiter untouched.
- Transparent UDP: `Rx::Datagram`, `Rx::Transparent` and `Rx::TransparentSplit` payloads are ranges of the caller's input buffer and are valid only until it is recycled; a driver (TUN read buffer, future XDP UMEM frame) must consume or copy them first. Only `Rx::TransparentOwned` owns its bytes. For `TransparentSplit`, each `packet[payload].chunks(size)` item is one datagram, last possibly shorter (at most 128); never merge those boundaries. `udp_send_from` fragments up to 64 KiB, queues at most 512 KiB (`Busy`), and the fragments leave through `poll_transmit`; `udp_send_gso_from` instead writes a USO run directly (at most 64 datagrams, each fitting the MTU, total UDP length and IPv4 total length at most 65535).
- Config defaults to keep stable: `mode` Endpoint, `half_open_max` 1024, `half_open_per_source` 128, `icmp_limits`/`fragment_limits` as above, `shared_budget` None, `tcp_chunk` None (Endpoint 16 KiB / transparent 4 KiB); `Config::chunk()` clamps explicit sizes to 4..=64 KiB. The two-chunk-plus-descriptors floor is about 33/9 KiB, not total idle commitment. TCP keepalive is per flow through `AcceptOpts`, off by default, failure is `TimedOut`.
- Offload is core API only, no device drivers yet: TCP GRO enters once as contiguous data and counts represented frames for ACK cadence; one cumulative ACK obligation per run, never replay duplicate ACKs. `poll_transmit_with` uses transparent `TxCaps::tso4`/`tso6` for TSO, retains one send descriptor per wire segment and emits `Transmit` with `GsoTx`/`TxCsum::Partial`; caps off is plain output, Endpoint ignores caps. `udp_send_gso_from` uses `uso4`/`uso6` for multi-datagram runs only in transparent mode, else `Offload`; a one-datagram payload uses ordinary `udp_send_from`. Drivers must segment and complete headers/checksums, not send an aggregate as a wire packet. No `TUN_F_TSO_ECN`.

### Driver invariants

- One `Mutex<Inner { stack, tunn, .. }>` per tunnel, one owner task per tunnel, held by the registry, not by any node's task owner. Lock holds are bounded to a 64-packet batch in both directions; nothing awaits under the lock.
- Wakers are registered under the same lock the owner uses to publish readiness. Every application call goes through `Shared::with`, which calls `take_tx_wakeup()` afterwards; `Notify` supplies the permit that prevents a lost wake-up.
- One live tunnel per (our private key, peer public key, endpoint host, endpoint port) per tunnel registry: key pairs reused across endpoints are different peers. A registry (`proxy/wireguard/registry.rs::Registry`) is created with the first `OutboundRuntimeRegistry` of a control plane and inherited by its reload successors (`build_reusing*`), DNS forks (`fork_for_dns`) and cold-probe runtimes (`ephemeral_guarded_after_admission`), so those share tunnels exactly as before while two planes (an embedder, or tests in one process) never see or close each other's. Node-only dials (honk-tool, hand-built nodes, `NodeRuntime::try_ephemeral*`) use `Registry::standalone()`, which no plane closes; its tunnels end by idling out. Identical `TunnelConfig` is shared within a registry; a different config for the same key and endpoint replaces the incumbent and closes its flows with `RuntimeClosed` (not a `NodeFailure`: the node ID may be unchanged across a reload). `network` and the node name are not part of `TunnelConfig` equality. The memory budget stays process-wide; the tunnel-count cap is per registry.
- The owner task ends on failure, replacement, `OutboundRuntimeRegistry::shutdown_wireguard_tunnels` (called once from `ControlPlane::shutdown_runtime` on the plane's current runtime registry; it joins every owner of that plane's tunnel registry, replaced ones included, and touches no other plane's tunnels nor the standalone registry; never from a candidate-epoch cleanup), immediately when the last runtime scope using the tunnel closes with no live flow or warm owner (`release`/`close_scope`), or after 120 s without a flow or warm owner (`Failure::Idle`, retryable by the dialer). `Finalize` fails the tunnel and removes it from its registry (held weakly) on any exit, including panic. Warm holds are counted per scope; a runtime installing the tunnel again must not drop the pin.
- Memory: honk-core calls `proxy::wireguard::init_memory_share` once (`ResourceBudget.wireguard_memory`). The share is one `MemoryBudget` (`Limits` in `registry.rs`) that every tunnel stack uses as `shared_budget`, with `memory_limit` = the share; never give tunnels fixed slices. Live tunnels are capped by their fixed non-budgeted cost, `share / 4 MiB` within 1..128 (`TUNNEL_FIXED_BYTES`: recompute it if a per-tunnel buffer grows); at the cap an unused tunnel is evicted, otherwise the dial gets `PacketRejection::Capacity`. The outer receive queue is requested at the share, capped at 64 MiB in `socket.rs`. Output buffers are capped (256 KiB) so a jumbo MTU stays cheap. Config validation caps the inner MTU at 65472 (outer datagram within one IPv4 UDP payload).
- Handshake: a waiter's timeout returns the attempt's shared episode to that waiter only and never fails the tunnel. Initiations are resent after 1 s and 2 s before boringtun's 5 s cadence (documented deviation); each resend rotates to the next resolved endpoint address; a timed-out attempt makes the next acquire re-resolve. `State::Established` means a live session (it lapses after 180 s), so `is_warm` and `warm` re-handshake after expiry.
- Reserved bytes are written after encryption and zeroed before decryption. Inbound sources and outbound targets must lie inside the allowed IPs (aggregated, binary-searched); targets are numeric (`to_canonical`), never resolved remotely.
- Failure provenance: refusal (inner RST, ICMP unreachable, disallowed target or family without a tunnel address, at TCP dial and UDP association open) is `TargetFailure`; per-packet UDP sends to other disallowed destinations are `Policy`; local exhaustion (`FlowLimit`, `Memory`, `AddrInUse`, tunnel cap) is `Capacity`; an unanswered SYN is a target failure only if `inner_rx` advanced during the dial; handshake timeout, session expiry with flows, and unexpected owner exit are one shared node-failure episode. Unauthenticated datagrams are dropped silently (no failure threshold) and a cookie reply is neither answered nor trusted. Handlers never report Score or health. WireGuard's own logs carry the node name (`node = %name`); boringtun's logs are silenced.
- Roaming moves the outer endpoint only on an authenticated datagram.

### Changing it

- A TCP behavior change needs a packet-script test (`tests/tcp_*.rs`) or a simulator case that fails without the production hunk; a recovery or pacing change also runs the `#[ignore]` grids once and says what they showed. Driver behavior changes extend `proxy/wireguard/tests/`, which talk to an independent boringtun + smoltcp peer, never to the code under test.
- Transparent behavior: packet scripts in `tests/transparent_tcp.rs`, simulator cases in `tests/sim_transparent.rs` and `tests/sim_termination.rs` (honk terminator `tests/sim/honk_server.rs`), the `netstack_transparent` fuzz target (`fuzz_checks/transparent.rs`, seeds `fuzz/corpus/netstack_transparent/`) and the transparent cases of `benches/stack.rs`. Offload contracts live in `tests/offload_rx.rs`, `offload_tx.rs`, `offload_memory.rs`, `offload_e2e.rs`; the benchmark's `OFFLOAD` switch defaults false and throughput counts represented wire segments. A change that moves a limit or contract above also updates the "Not implemented yet" list in the design doc.
- Core packet lifetime/credit tests live beside `control/netstack`; real packet/loopback TCP integration lives in `control/connection/tcp_packet_tests.rs`, and scoped UDP plus supervisor cancellation in `control/packet_endpoint/tests.rs`. These prove Endpoint behavior, not device capture/X0/X1 or whole-process memory accounting.
- A new TCP mechanism that adds a state, queue or hint also extends `Stack::check`/`Tcb::check_invariants` and, when it is reachable from the wire, the `fuzz_checks` seeds. Replay with `just fuzz-replay` (stable); grow inputs with `just fuzz netstack_packet` / `netstack_schedule` / `netstack_transparent`, and commit any crash as `fuzz/artifacts/<target>/` plus its fix. `fuzz/seed.sh` regenerates the netstack seeds.
- Gate: `just outbound-ci` (fmt, clippy `-D warnings`, honk-config, honk-netstack, honk-outbound). Stack-only changes may run `cargo test -p honk-netstack` first; it takes seconds.
- Performance or loss-recovery claims need lab evidence on the `bench` branch (`bench/netstack/`); simulator numbers are not a substitute. Say which arm was measured. Transparent mode has no performance gate or number.
- Update `doc/en/design/netstack.md` and `doc/zh/design/netstack.md` together with `lib.rs` and this file when a limit, default or driver contract changes; node field changes also update `doc/*/reference/nodes.md`.

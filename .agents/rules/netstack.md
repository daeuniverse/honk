## Netstack and WireGuard

Read with: `AGENTS.md` (Notes for agents: the netstack paragraph); `test-locations.md` for suites; `doc/en/design/netstack.md` (mechanisms, limits) and `doc/en/design/outbound.md#wireguard-tunnel` (driver specification); `configuration.md` for node fields and identity.

### Layout

- `crates/honk-netstack/src/`: `stack.rs` (public API, class rotation, DRR), `flow.rs` (generation slab, RFC 6056 ports, RFC 6528 ISN, TIME_WAIT table), `timer.rs` (lazy min-heap), `udp.rs`, `icmp.rs`, `wire/` (codecs and checksum), `tcp/` (`mod`/`input`/`output` state machine; `ring` chunk pool, floors and commitment; `sent` scoreboard; `sack`; `rack`, `recovery`, `prr`; `rtt`; `cc` + `cubic`; `pacing`). `fuzz_checks/` (feature `fuzz-checks`) holds the replayable fuzz properties; `benches/stack.rs` and `tests/alloc_free.rs` the per-packet cost and zero-allocation check; `tests/idle_footprint.rs` the idle per-flow heap and `tests/shared_budget.rs` the process budget. `lib.rs` documents the driving contract; keep it true.
- `crates/honk-outbound/src/proxy/wireguard/`: `mod.rs` handler, `registry.rs` per-plane tunnel registry and `TunnelConfig`, `tunnel.rs` shared state and owner task, `socket.rs` marked outer UDP with GRO/GSO, `stream.rs` TCP `FlowIo` and dial, `udp.rs` shared-source UDP. `runtime/wireguard.rs` is the per-runtime slot (it holds its plane's registry); `descriptor.rs` registers the protocol.
- Config side: `honk-config/src/node/wireguard.rs`, `share_link/wireguard.rs`, and the Clash/sing-box mappings in `honk-core/src/subscription/`; they follow `configuration.md`.

### Stack invariants

- Sans-I/O: `forbid(unsafe_code)`; dependencies are `blake3` and `thiserror` only (`smoltcp` is a dev-dependency pinned to `=0.14.0` so the baseline keeps measuring the same code). The crate reads no clock, environment or file; time arrives as `Instant` arguments and the secret and limits in `Config`.
- One owner, `&mut Stack`. Every pending output is flow state; no unbounded or silently lossy queue. The only dropping queues are bounded and counted: control replies (128, `control_dropped`) and the OOO range table (32 ranges, `ooo_drops`). A caller that stops pulling `poll_transmit` loses nothing.
- Every call that can create a send obligation (`tcp_write`/`shutdown`/`close`/`abort`/`connect`, a `tcp_read` that makes a window update due) must set `tx_wakeup`; the driver wakes its owner on `take_tx_wakeup()`.
- All `receive` calls of a batch use the same `now`. RTT, RACK and autotuning must not see processing time.
- RX checksums are verified before any state is touched, for every protocol. No trusted mode. TX checksums are computed during the payload copy.
- Memory: every admitted TCP flow owns a floor (one TX chunk, one RX chunk, 16 descriptor slots) charged at admission; the remainder is the shared pool. A receive window is advertised only after it has been committed from the pool; the highest advertised right edge is never withdrawn and wire rounding goes down only. Accounting is by capacity, not logical bytes. The floor is a guarantee, not resident memory: an emptied ring returns every chunk and an idle `Sent` returns its descriptor storage. `Config::shared_budget` (`budget.rs`) is charged next to the pool's own limits and only from `Pool`; floors at `tcp_connect`, refunded where a flow retires, everything else refunded by `Pool`'s `Drop`. Do not add an allocation path that bypasses `ring.rs`'s `Pool`.
- Counters (`packets_out`, `sacked`, `lost`, `retrans`) are incremental; `Sent::check` recounts them (and checks descriptor order, cursors and the remembered SACK runs) in debug builds and must keep running after every method that mutates the scoreboard; `Stack::check` (feature `fuzz-checks`) recounts the flow table, timers and queues.
- Fixed point only in congestion control (`cubic.rs`); do not introduce floating point.
- ICMP is consumed only for an outstanding quoted TCP sequence and never generated; fragments are dropped. Changing either is a design change, not a fix.
- RTO floor 200 ms is intentional (shared with Linux; TLP covers it). Timestamps, SACK and window scaling are always offered.

### Driver invariants

- One `Mutex<Inner { stack, tunn, .. }>` per tunnel, one owner task per tunnel, held by the registry, not by any node's task owner. Lock holds are bounded to a 64-packet batch in both directions; nothing awaits under the lock.
- Wakers are registered under the same lock the owner uses to publish readiness. Every application call goes through `Shared::with`, which calls `take_tx_wakeup()` afterwards; `Notify` supplies the permit that prevents a lost wake-up.
- One live tunnel per (our private key, peer public key, endpoint host, endpoint port) per tunnel registry: key pairs reused across endpoints are different peers. A registry (`proxy/wireguard/registry.rs::Registry`) is created with the first `OutboundRuntimeRegistry` of a control plane and inherited by its reload successors (`build_reusing*`), DNS forks (`fork_for_dns`) and cold-probe runtimes (`ephemeral_guarded_after_admission`), so those share tunnels exactly as before while two planes (an embedder, or tests in one process) never see or close each other's. Node-only dials (honk-tool, hand-built nodes, `NodeRuntime::try_ephemeral*`) use `Registry::standalone()`, which no plane closes; its tunnels end by idling out. Identical `TunnelConfig` is shared within a registry; a different config for the same key and endpoint replaces the incumbent and closes its flows with `RuntimeClosed` (not a `NodeFailure`: the node ID may be unchanged across a reload). `network` and the node name are not part of `TunnelConfig` equality. The memory budget stays process-wide; the tunnel-count cap is per registry.
- The owner task ends on failure, replacement, `OutboundRuntimeRegistry::shutdown_wireguard_tunnels` (called once from `ControlPlane::shutdown_runtime` on the plane's current runtime registry; it joins every owner of that plane's tunnel registry, replaced ones included, and touches no other plane's tunnels nor the standalone registry; never from a candidate-epoch cleanup), immediately when the last runtime scope using the tunnel closes with no live flow or warm owner (`release`/`close_scope`), or after 120 s without a flow or warm owner (`Failure::Idle`, retryable by the dialer). `Finalize` fails the tunnel and removes it from its registry (held weakly) on any exit, including panic. Warm holds are counted per scope; a runtime installing the tunnel again must not drop the pin.
- Memory: honk-core calls `proxy::wireguard::init_memory_share` once (`ResourceBudget.wireguard_memory`). The share is one `MemoryBudget` (`Limits` in `registry.rs`) that every tunnel stack uses as `shared_budget`, with `memory_limit` = the share; never give tunnels fixed slices. Live tunnels are capped by their fixed non-budgeted cost, `share / 4 MiB` within 1..128 (`TUNNEL_FIXED_BYTES`: recompute it if a per-tunnel buffer grows); at the cap an unused tunnel is evicted, otherwise the dial gets `PacketRejection::Capacity`. The outer receive queue is requested at the share, capped at 64 MiB in `socket.rs`. Output buffers are capped (256 KiB) so a jumbo MTU stays cheap. Config validation caps the inner MTU at 65472 (outer datagram within one IPv4 UDP payload).
- Handshake: a waiter's timeout returns the attempt's shared episode to that waiter only and never fails the tunnel. Initiations are resent after 1 s and 2 s before boringtun's 5 s cadence (documented deviation); each resend rotates to the next resolved endpoint address; a timed-out attempt makes the next acquire re-resolve. `State::Established` means a live session (it lapses after 180 s), so `is_warm` and `warm` re-handshake after expiry.
- Reserved bytes are written after encryption and zeroed before decryption. Inbound sources and outbound targets must lie inside the allowed IPs (aggregated, binary-searched); targets are numeric (`to_canonical`), never resolved remotely.
- Failure provenance: refusal (inner RST, ICMP unreachable, disallowed target or family without a tunnel address, at TCP dial and UDP association open) is `TargetFailure`; per-packet UDP sends to other disallowed destinations are `Policy`; local exhaustion (`FlowLimit`, `Memory`, `AddrInUse`, tunnel cap) is `Capacity`; an unanswered SYN is a target failure only if `inner_rx` advanced during the dial; handshake timeout, session expiry with flows, and unexpected owner exit are one shared node-failure episode. Unauthenticated datagrams are dropped silently (no failure threshold) and a cookie reply is neither answered nor trusted. Handlers never report Score or health. WireGuard's own logs carry the node name (`node = %name`); boringtun's logs are silenced.
- Roaming moves the outer endpoint only on an authenticated datagram.

### Changing it

- A TCP behavior change needs a packet-script test (`tests/tcp_*.rs`) or a simulator case that fails without the production hunk; a recovery or pacing change also runs the `#[ignore]` grids once and says what they showed. Driver behavior changes extend `proxy/wireguard/tests/`, which talk to an independent boringtun + smoltcp peer, never to the code under test.
- A new TCP mechanism that adds a state, queue or hint also extends `Stack::check`/`Tcb::check_invariants` and, when it is reachable from the wire, the `fuzz_checks` seeds. Replay with `just fuzz-replay` (stable); grow inputs with `just fuzz netstack_packet` / `netstack_schedule`, and commit any crash as `fuzz/artifacts/<target>/` plus its fix. `fuzz/seed.sh` regenerates the netstack seeds.
- Gate: `just outbound-ci` (fmt, clippy `-D warnings`, honk-config, honk-netstack, honk-outbound). Stack-only changes may run `cargo test -p honk-netstack` first; it takes seconds.
- Performance or loss-recovery claims need lab evidence on the `bench` branch (`bench/netstack/`); simulator numbers are not a substitute. Say which arm was measured.
- Update `doc/en/design/netstack.md` and `doc/zh/design/netstack.md` together with `lib.rs` and this file when a limit, default or driver contract changes; node field changes also update `doc/*/reference/nodes.md`.

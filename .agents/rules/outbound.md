## Outbound and transports

Read with: `AGENTS.md` (Technology stack, Runtime invariants); `score.md` for Score attribution of transport outcomes; `configuration.md` for VLESS configuration and node identity; `test-locations.md` (Suite map: Runtime and transport) for the suites.

### Module ownership

Outbound source ownership: `proxy/{error,packet,outbound,registry}.rs` retain the public proxy facade; Shadowsocks owns `aead2022`/`stream`, and VLESS owns feature-only `handler`/`encryption` plus `cool`/`mux` backends. Shared UoT, transport and REALITY stay outside VLESS. QUIC owns `path_health`, `flow_control`, `metrics`, `endpoint`, `client`, `stream` and `boring`; the public `quic_boring` facade remains supported. AnyTLS uses `padding`/`writer`/`overflow` plus the shared `uot` non-connect transport. Alive uses `health`/`urltest`, and SessionPool uses `maintenance`/`speculative`; common state stays at each ancestor to avoid widening fields. Normal builds without `rprx` allocate no VLESS pools/carrier semaphores; `cfg(test)` retains backend-only unit coverage, never handler registration.

### gRPC and XHTTP

Shared gRPC lives in `proxy/transport/grpc.rs`: `h2` owns HTTP/2 and connection-wide HPACK with a 64 KiB response-header limit and its default 4 KiB dynamic table. The returned stream owns the driver/socket; split readers and writers share stable driver wakeups. At most one 16 KiB application message is queued, and flush waits for both its ownership release and physical I/O flush, including after peer window reductions. Preserve buffered payload before terminal read errors, retained read outcomes, request half-close, and graceful GOAWAY for an admitted stream; never replay application bytes.

XHTTP is a node-owned H2 transport in `proxy/transport/xhttp/` (`browser`, `preparation`, `request`, `response`, `runtime`, `session`, `stream`, `upload`); requests without a configured User-Agent carry Xray's Chrome `fetch()` headers; gRPC and XHTTP share the H2 byte-queue tracking in `proxy/transport/h2_io.rs`, and `runtime/pooled.rs` owns the pooled-session lifecycle dispatch (AnyTLS, VLESS, XHTTP). Per node generation there are 128 logical flows and, per peer (upload, plus a GET-only download peer from download settings), at most two reusable carriers (a draining carrier may overlap its replacement), 128 request slots per carrier, 16 KiB streaming writes, and 256 KiB stream / 4 MiB connection receive windows; each packet-up flow has at most eight outstanding POST responses, and only VLESS holds the process carrier permit. Each carrier retains up to 2048 locally reset requests (16 admission windows) for h2's default one-second in-flight-frame grace period and keeps its bounded default lifetime budget of 1024 protocol-error resets. A speculative UDP candidate publishes its carrier only at winner commit, whatever the multiplex path; a draining carrier still publishes drain-only. stream-up shutdown completes once the request END_STREAM is flushed while its response keeps draining, and any later status or reset still fails the flow. Never replay application bytes after HEADERS acceptance.

### Connection establishment

UDP establishment orchestration stays in `control/connection/udp.rs`, candidate preparation and shared-source path selection in `udp/dial.rs`; endpoint/driver publication and the first application send remain in the initializer.

### UDP transport invariant

Ordinary production endpoints use `PacketTransport`; source-shared protocols use core-owned source transports with endpoint send views and one receiver: concrete VLESS XUDP/Mux.Cool, Hysteria2 and TUIC arms, and one generic `Shared` arm for every `MultiTargetTransport` (Shadowsocks, Juicity, SOCKS5, Trojan, AnyTLS, VLESS UoT v2 and H2MUX), selected through the protocol registry's shared-source slot. Tunnel handlers frame datagrams directly: Trojan, native VLESS UDP, AnyTLS and VLESS UoT v2 (non-connect, address per packet), VLESS H2MUX (PacketAddr), VLESS XUDP/Mux.Cool, Shadowsocks, TUIC/Hysteria2, and Juicity. Direct and SOCKS5 hide raw sockets behind the same contract; no loopback bridges remain. `UdpEndpointPool` retires dead transports rather than black-holing flows.
The core source index is keyed by reused runtime identity, normalized client, protocol/UDP path, and `ActualPeer` or `RewriteTo(original destination)`. It owns one logical protocol association, one receiver, and multiple endpoint send views per scope; the full `(client, destination)` endpoint map remains authoritative for routing, decision token, and per-flow Score. An occupied wrong-owner, `Initializing`, or `Retiring` entry is a drop, never a foreign reply. Only an absent `ActualPeer` key may use foreign-reply delivery, without per-flow Score; domain rewrites stay pinned to their original destination. Source ownership and joined shutdown of every non-VLESS protocol work without `rprx`; only VLESS alternatives require it.
`MultiTargetTransport` associations carry every destination of one client source on one logical association (one SS2022 session with a single session ID, packet counter and replay windows; one Juicity stream; one SOCKS5 control connection and relay; one Trojan associate stream; one non-connect UoT v2 or H2MUX PacketAddr stream) and return the server-reported real peer from `recv_packet`: IPv4-mapped peers are IPv4, a domain source is accepted only as the captured domain and port, any other domain is dropped without DNS (stream protocols consume the frame whole), and an unknown address type stays terminal; undecodable or unprojectable Shadowsocks datagrams still drop only themselves. A per-packet destination name is sent only when it is exactly the name the association was dialed by, otherwise the numeric target (Shadowsocks, SOCKS5, Trojan, AnyTLS, VLESS UoT/H2MUX; Juicity forwards the supplied name and has no real-peer evidence): real servers (sing-box) fix the destination form by the first packet and drop the association on a mismatched spelling. `send_packet` and `send_to` share one unboxed helper; `confirmed` reaches the transport only on a view's first send and `admitted` means the datagram reached the wire path or writer queue; a send that times out before `admitted` is packet-local congestion whatever the carrier, until the source's uplink stall limit below. Partial-frame timeouts of reliable-stream carriers (Trojan, Juicity, AnyTLS) stay terminal for the whole source, and a frame write cancelled halfway (for example by a retired view) poisons the Trojan, Juicity, UoT and H2MUX stream (`FramePoison`) so the next send fails with the typed `FrameInterrupted` instead of extending a torn frame; core retires the source neutrally when a retired view caused the tear. A native UDP size refusal (`EMSGSIZE`) is a typed local `InvalidSize` rejection, not a transport failure. `source.send_gate` is the outer lock and backends hold only leaf locks beneath it, never calling core; the last view's endpoint permit stays held until the source receiver exits or another view binds. Explicit VLESS `native` stays unshareable, and Auto keeps native UDP on 53/443 without Vision because Single XUDP measured about half the goodput and 1.9-3.3× the CPU per MB.
The VLESS source ID is a runtime-lazy private keyed hash. Reusing a runtime and replacing only a carrier preserves it; replacing/restarting the runtime changes it. This preserves honk's per-source semantics, not Xray's global-ID identity or collision-free NAT. Hy2 Session IDs and TUIC association IDs belong to their actual QUIC connection; physical connection reuse does not merge distinct source associations. Late local callbacks are owner/token fenced, and no cancelled or ambiguous packet is replayed automatically.
Hy2/TUIC retain concrete reply peers in the existing bounded reassembly entries; TUIC continuation `None` waits for fragment zero, including out-of-order arrival. Known captured domain/port projection is distinct from a foreign IP and never starts DNS. Keep TUIC zero-length datagrams and Hy2's existing empty-inbound rejection. Source QUIC tokens start only after the send gate but stay driver-owned through timeout classification; dropping a timed-out send future must not substitute token failure for timeout. Gate waits consume the existing deadline. Preserve datagram versus stream cancellation/congestion and keep VLESS-only empty-first/poisoned-child rules local.
Capture terminal per-flow Score before synchronous health callbacks; shared-source `DataUdp` health belongs to the source, so an unreplied view cannot demote an already-replied source. Preserve health-neutral policy/size/capacity rejection, packet-local congestion, idle-after-reply, retirement and shutdown; an uninterrupted 30 s run of unadmitted deadlines is a transport failure, QUIC retains its own path-health classification, and `PacketRejection::Capacity` stays terminal through wrappers, DNS retries and CLI projection.
`SharedError` preserves the causal chain for all waiters on DNS and reusable-session initialization. Terminal packet refusal must survive outer route retries, name-family aggregation, and fallible health/URLTest resolver hooks; never replace it with system/bootstrap DNS or a default probe target. Preserve ordinary-error and configured-literal fallback behavior.
Authoritative and cold URLTest UDP preparation return generic `PreparedUdpTransport<T>` values. Only the selected value's fallible commit may publish and return its `Arc<T>`; losing/dropped preparations roll back. They share one absolute `max(10s, 4 × connect_timeout)` deadline, including winner commit. Policy is checked at actual candidate admission; rejection terminates and drains without sibling/direct fallback. Deadline expiry drains started preparations; cancellation and never-started candidates are health-neutral, while completed transport failures still count. Endpoint publication and the separately bounded first send follow successful commit.

### VLESS runtime and pools

VLESS runtime/pool ownership lives in `honk-outbound/src/runtime/vless.rs` and `proxy/vless/{handler,mux,cool}.rs`; the control plane owns source sharing in `honk-core/src/control/udp_endpoint/source.rs`. One process VLESS-carrier semaphore, carved from the startup FD partition before UDP endpoints and shared across reload and DNS forks, is authoritative. Its permits cover actual carrier I/O through active, provisional, draining, and idle task teardown. H2 keeps its own two-carrier/128-concurrent-stream bound and has no 128-open lifetime; Mux.Cool has no per-node two-carrier cap, admits at most the configured positive concurrency capped at 128 per carrier, and rolls a carrier after 128 issued IDs. The existing maintenance pass reaps unretained idle VLESS carriers; do not add a protocol timer.
Resolve warm retention and runtime reuse by `WarmRequirement::Session` or `WarmRequirement::Udp`; a runtime selected only by UDP Xray mux remains eligible for bare TCP use.
Pool waiters register capacity notifications before checking availability. Detached attachment returns its first pool-owned stream permit; all releases, carrier publications, backend close/drain transitions and closed-carrier pruning notify waiters, including non-reserving warm offers. Bind each backend to its owning pool notification before publication or detached attachment.
Source send start/completion, matching retirement intent, and endpoint/source-view retirement publication share the existing source-state mutex. Release transition guards before pool retirement or unavailable-health callbacks; never hold them across await. Positive availability reports retain their admission fence.
Source retirement publishes its Score disposition with admission closure. The common endpoint Score finalizer preserves that disposition for bound views; never-bound or previously retired views retain their local result. Snapshot source state before reporting, without holding it across Score callbacks.

## Configuration

Read with: `AGENTS.md` (Notes for agents: node identity, group filters, documentation rule); `real-ebpf.md` for the `ebpf` feature and NFQUEUE activation; `security.md` for the settings with security consequences; skill `honk-config-change` for the change steps.

Only documented format: original **dae syntax**, `{ include { ... } global { ... } node { ... } group { ... } routing { ... } dns { ... } subscription { ... } experimental { ... } }`, parsed by `honk-config/src/parser/mod.rs`. `include` accepts bare/quoted `.dae` globs, entry-relative; merge entry sections first, reject repeated/cyclic/escaping files. Examples: `config.dae` (full), `config.min.dae` (minimal), `example.dae` (annotated). Reference: `doc/en/reference/`; guide: `doc/en/configuration.md`.

- Canonical VLESS configuration lives only in `src/node/vless.rs`: `VlessConfig.network` controls UDP permission, `VlessUdpEncoding::{Auto,Native,Xudp,UotV2}` controls protocol framing, and `VlessMultiplex::{Off,H2,Xray}` independently controls multiplexing. Xray owns signed TCP/XUDP concurrency and `Udp443Policy`; H2 owns its padding flag. `src/share_link/options.rs` and `src/node/wire.rs` are adapters into this model, not parallel mode models.
- VLESS permits UDP/443 by default, including base Vision; users block QUIC through routing. Xray `Udp443Policy` defaults to `Allow`, while explicit `Reject` and UDP-disabled remain terminal. `Skip` selects protocol fallback without an implicit Vision port gate. Normalize the `xtls-rprx-vision-udp443` input spelling to base Vision before identity/runtime reuse; never let that spelling override explicit packet policy.
- VLESS `vless_mode` has been removed: reject its raw presence, including `null`, rather than interpreting an alias. Static entries reject the candidate config; subscriptions salvage other valid entries, but an all-old-mode cached body cannot restore offline. The same flat field on a non-VLESS serde record remains only a compatibility artifact; do not change VMess behavior or identity through VLESS cleanup. Normalize before `Node::derive_id`; every admitted VLESS node is re-derived with a new ID at this upgrade, not only nodes with an explicit old mode. Name-based persisted Selector choices and valid TCP-v4 delays no older than 24 hours can survive; delay restoration is not liveness restoration.
- Share-link VLESS failures carry `DetailedConfigError` from their origin; schema fields and safe reasons are not reconstructed from legacy prose. Public legacy APIs project only at the exit. `node/wire.rs` derives flat serialization from its complete borrowed output view; input raw-presence validation remains separate.
- VLESS identity separates plaintext from TLS while keeping REALITY's effective transport independent of a redundant TLS flag. Share-link `security`/`tls` claims coalesce only when equal and reject contradictions. VLESS and Trojan map REALITY intent through shared TLS options; unsupported share-link schemes reject that intent instead of silently using ordinary TLS.

Parser layout (`crates/honk-config/src/parser/`): `cursor.rs` pulls physical-line tokens from the shared `lexer.rs` and indexes balanced roots and bounded segments. Ordinary quotes open at token head or after unquoted `(` or `,`; only root `include` enables adjacent quoted paths before comment/brace classification. Standalone `Source::tokenize` retains the ordinary lexical rules. `read.rs` supplies forward delimiter traversal over source-backed spans; section readers interpret their own grammars, and the file loader keeps include path splitting, ordering and confinement. Quote errors come from token coordinates, and the outer attempt publishes one terminal after merging notices without changing caller prefixes. Entry tags beginning with a quote require a colon immediately after its closing quote (allowing whitespace); suffix colons are data. Glued entry-tail truncation does not hide structural braces.
Pending structural headers accumulate their unquoted-colon classification once; token inspection skips ordered quoted spans instead of rescanning them for each punctuation byte.
Only entry/standalone dae admission requires a block; included fragments use the same structural checks without that format gate. Segments distinguish accepted/ignored statements and compact/braced blocks; declaration bodies allow dynamic headers, while scalar/rule value delimiters prevent premature compact splitting. Legacy trailing `{}` remains a block form. Comment-brace notices are classified with the live cursor scope and emitted once before EOF checks. Filter diagnostics retain original lexer-error provenance, and sibling node/subscription/group traversal resets semantic notice ownership.
Body syntax distinguishes statements, dynamic declarations, line-local entries and multiline expressions. Parenthesis shielding carries across returned expression statements from the same source, never through skipped block headers or across source boundaries. Compact splitting cannot detach an already-indexed opener from its header. Subscription raw-field views include the full opening token (`{` or `{}`), independently of the structural header span.
Ignored statement heads are classified before compact splitting or parenthesis updates; readers consume that admission result instead of rediscovering it after splitting. Entries stop early declaration splitting once a quoted value head or a populated tag/URI value begins, while tag-only headers and legacy trailing compact blocks retain their existing behavior.

`honk-core/src/config_diagnostics.rs` owns active static/provider diagnostics and the safe `/configs` projection. Public full reload takes `DiagnosticBuckets`, preserving provider ownership rather than flattening rows into static diagnostics. Runtime updates explicitly preserve same-source provenance, replace full provenance, rebase static-file diagnostics, or replace one admitted provider; provider updates carry only that provider's rows until commit. SIGHUP retains diagnostics only for provider bodies retained by rebasing. Snapshot order is static, configured providers in declaration order, then admitted non-worker providers in bucket order. Acquire the config lock before the diagnostics lock; the config writer is the joint publication barrier, under the existing serialized reload path. Failed/stale updates and empty provider updates retain active diagnostics; successful unchanged-input updates may replace provenance without advancing the DNS/runtime generation.
Full diagnostic replacement rejects duplicate provider UUIDs at the common runtime admission boundary before any no-op or publication shortcut.

Held-first-packet UDP has exactly one `global` key:

```dae
global {
    nfqueue_enable: true
}
```

Legacy `experimental { udp_nfqueue { enabled: ... } }` warns and migrates to `global.nfqueue_enable`; never serialize the removed section.

Default on; restart-required. Activation requires the real eBPF backend and an `ebpf` build.
Mock/no-`ebpf` startup or failed fixed-queue preflight warns and disables staging
for this process, never rewriting config. Set `false` for unprivileged mock development.
Only LAN-forwarded UDP: `inet prerouting` follows LAN TC; host WAN egress stays TPROXY.
Ordinary staging excludes DNS 53, internal/special, reverse, must/block and safe direct. Fragmented LAN UDP53 needing controller/raw delivery instead uses kernel reassembly followed by the same queue, without ordinary conn-state/tokens. Disabled/unready NFQUEUE drops those fragments; unfragmented DNS and native direct-must remain unchanged.
No queue/worker/timeout/failure knobs: queue `320` and fail-closed behavior are fixed.
Owned nftables names and firewall restrictions: `crates/honk-nfqueue`.

- Group policy: omitting `policy` selects `Selector`; `policy: score` selects the always-compiled `Score` policy. Legacy `honk` is invalid. Score has no configuration knobs.
- Built-ins: `honk-core` injects `direct`/`block`, not the parser (see `honk-config`'s `ensure_builtin_nodes()`). User nodes using those names or `NodeProtocol::Direct`/`Block` fail validation. `block` drops traffic.
- `src/config.rs` — `Config` / `GlobalConfig` (~40 global fields), `from_file` / `to_file` / `validate`, JSON helpers. Idempotent `ensure_builtin_nodes()` injects `direct`/`block` with reserved `NodeProtocol::Direct`/`Block` and stable `DIRECT_NODE_ID`/`BLOCK_NODE_ID` UUIDs. **The crate never calls it**: `honk-core/src/lib.rs` calls at startup/SIGHUP; other consumers must call explicitly.
  DNS upstream-reference checks live in `src/dns/validation.rs` and share `DnsRouting::request_source` with `effective_request`, retaining current/legacy field paths with one-based diagnostic ordinals. `Config::validate` is the legacy projection of `validate_detailed`; startup/SIGHUP and public reload use detailed admission, with assembled membership checks before publication. Parse-only Config loaders do not perform whole-config admission.
  Successful routing/DNS/subscription reference checks do not construct diagnostic paths; paths are allocated only on rejection. Active legacy DNS fallback diagnostics distinguish undeclared empty and default `upstream` values using static codes without exposing names.
- Interface modes: absent `global.lan_interface` means no LAN hooks, never implicit `lo`; configured `wan_interface` hooks still proxy host TCP/UDP. Unresolved `auto` stays pending/fail-open until an IPv4 default route appears. On link/address/route events, `IfaceWatcher` attaches single-/dual-homed programs without restart, observes interface addresses for topology/ECS, immediately re-probes health-backed outbounds, and follows WAN bond slaves. Startup/reload/network events never synthesize gateway-address routing rules; preserve user rule order and use [explicit local rules](../../doc/en/reference/routing.md#explicit-local-rules). WAN-only still requires `dae0`/`daens`, transparent listeners, cgroup hooks, bypass marks.
  Real LAN self-protection is advisory: inspect the canonical compiled rules for unconditional `direct(must)` coverage of observed configured-interface addresses on non-53 TCP/UDP ports at startup, traffic-policy commit and network changes. Unknown predicates/partial port coverage may warn; never reject configuration, synthesize rules or treat this as a connectivity guarantee.
- Health: `global { tcp_check_url, udp_check_dns, check_interval, check_tolerance }`. Selector leaves stay warm as specified in `doc/en/design/groups.md` (Warm-up and ownership). `udp_warm_node_count: 0` disables the separate UDP warm set; positive values warm each group's top-N (≤3) reusable UDP leaves after every probe cycle. Dial modes: `ip` / `domain` / `domain+` / `domain++`.
  HTTP execution is shared in `honk-outbound/src/urltest.rs`: `http_probe_request`, `health_http_probe_request`, `warm_http_probe`, and `measure_http_probe`; URL interpretation belongs to `honk-config::check`. Keep canonical credential-free authority/non-default ports, strip fragments, and preserve raw path/query (including dot segments and `/?query`). Fallible runtime admission precedes warming, feedback, and dialing. Core's `ProxyHttpProber` only adapts configuration, generation scope, and Score feedback. Verified TLS negotiates h2/http/1.1 with push disabled; measure the configured method after a HEAD warm-up, validating decoded final statuses 200–499. HTTP/1 informational and final heads share a 16 KiB per-round cap; partial heads fail even on timeout. Pre-response loss/timeout, graceful H2 GOAWAY and a remote H2 `REFUSED_STREAM` can fall back to the validated first RTT. H2 response header lists are capped at 16 KiB and its driver is cancellation-owned. Warm-up, dial, TLS, H2 startup and each exchange have separate budgets; core retains its connect timeout. Health, per-group URL state and delay strikes stay separate; UDP/QUIC probing and generation retention are unchanged.
  Fail a disposable H2 probe connection on its first locally detected protocol error, before a later remote reset can overwrite the rejection and trigger warm-sample fallback.
  Retain cancelled H2 stream records for twice the per-round timeout, covering both request budgets. Each probe owns at most two streams; completion or cancellation releases the connection without waiting for record expiry.
  Known deferred P2: `h2` 0.4.19 turns a missing response `:status` into decoded 200; honk cannot recover that omission after decoding. Track https://github.com/hyperium/h2/issues/958 and wait for upstream rather than applying a local fork/vendor patch. Do not claim complete HTTP/2 wire-status validation while this limitation remains.
- Subscription recovery: `global.store_subscribe` defaults `true`, retaining the last valid raw response per request identity. `honk-core/src/subscription/store.rs` owns the FD-relative store and fallback order; `subscription/supervisor.rs` restores stored bodies only at startup, before refresh. SIGHUP carries current nodes but does not read stored bodies. Process-scoped; reject SIGHUP changes as restart-required.
  Subscription decoders admit normalized entries incrementally through one body owner. Retain at most 128 nonterminal diagnostics per body plus one omitted-count summary and a separate terminal error; caller prefixes and valid-node/first-usable admission remain intact. URI diagnostics stream without an entry-local vector. Record option ownership lives in `subscription/records/options.rs`; adapters share the equal-claim fold in `honk-config::options::vocab` while retaining dialect-specific parsing and credential bytes.
- DNS bind: absent/empty disables only standalone listening, not transparent TCP/UDP port-53 interception. Bare numeric `IP:port` is UDP-only; `udp://host:port`, `tcp://host:port`, `tcp+udp://host:port` select transports. Accept schemed hostnames, bracketed IPv6, empty wildcard hosts; require port. Bind host-netns sockets all-or-nothing; semantic SIGHUP changes require restart.
- DNS hosts: repeatable `dns.use_host`, default no sources. `true` adds standard `/etc/hosts`; paths add OxiDNS-compatible exact/domain/regexp/keyword rules. Merge in declaration order, later duplicates win. Relative files select the first existing copy under configured `global.data_dir`, then `/var/share/honk`, then CWD; missing files stay under `global.data_dir`. Known IN A/AAAA names precede request rules/cache; missing families return NODATA without upstream I/O. SIGHUP transactionally reloads every source; load failure leaves the active generation untouched.
- DNS projection (`honk-core/src/dns/projection/`): retain at most 10,000 domain owners; admit at most 49,152 canonical IP keys into the 65,536-entry domain map, with at most 32,768 zero bitmaps selected for desired/reload state. Obsolete zero facts awaiting deletion may exceed that sub-limit within the applied total. Shared incremental/reload admission evicts zero facts first, then the highest IP; IPv4/mapped-IPv6 owners OR into one key. Keep 16,384 slots outside DNS projection for sniff writes. At the applied ceiling, new keys wait for confirmed removal, including on retry; the worker drains ready 256-entry batches without another observation. Omitted facts retain existing dial-mode/must/block cache-miss semantics, not blanket unknown-to-punt behavior. Headroom limits: `doc/en/design/dns.md` (Routing projection) and its `doc/zh` twin.
  Reload acknowledges the exact installed IP slice before owner reconciliation; skipped map publication preserves applied state. Worker writes and acknowledgements share the generation fence. Retry wakeups and batch admission use the same capacity-aware per-IP deadline; no separate retry heap can wake blocked insertions.
  Accepted uncacheable positives retain routing facts using the minimum positive non-OPT wire TTL (60s when absent); cache eligibility must not turn their projection lifetime into zero. Cacheable outcomes retain their effective lifetime, including remaining cache-hit and served-stale TTLs.
- DNS upstream URI schemes: `udp://` (bare default), `tcp://`, `tcp+udp://`, `tls://` (DoT), `https://` (DoH), `h3://`/`http3://` (DoH3), `quic://` (DoQ); optional dial-path proxy `name: 'uri' -> <node|group>` (or legacy `outbound:` key).
- Clash UI: `experimental.clash_api.external_ui_download_url` selects HTTP(S) dashboard ZIP; empty uses built-in zashboard. `HONK_UI_DOWNLOAD_URL` overrides both. Nonempty `external_ui_download_detour` forces the initial download and every redirect through its node/group; empty uses per-URL traffic routing. Both config fields require restart.
- Geo assets: `geoip.dat` / `geosite.dat` are selected only from regular files, in order `$DAE_LOCATION_ASSET`, configured `global.data_dir`, `/var/share/honk`, CWD, `/usr/local/share/honk`, `/usr/share/honk`, `/usr/local/share/dae`, `/usr/share/dae`, then `/etc/dae`.
- Environment variables: `RUST_LOG`; `HONK_UI_DOWNLOAD_URL` (highest-precedence UI ZIP URL override); `HONK_POOL_DISABLE=1` (bypass pool); `HONK_MI_COLLECT_SECS` (mimalloc-only per-owner park/sweep interval, default 60s, `0` disables).
  `HONK_VMLINUX_BTF` overrides real-eBPF raw kernel BTF for `pname` offsets; otherwise search `/sys/kernel/btf/vmlinux`, then `/usr/lib/debug/boot/vmlinux`. Unavailable kernel argv capture synchronously falls back to thread `comm` in the cgroup hook. Configure UDP NFQUEUE only via `global.nfqueue_enable`, never environment variables.
- Default runtime paths: config `/etc/honk/config.dae`, BPF pin root `/sys/fs/bpf`, embedded BPF object unless `--bpf-object`.

CLI (`honk-core` binary):

- Flags: `--config/-c` (default `/etc/honk/config.dae`), `--log-file` (process-local override of `global.log_file`), `--bpf-object/-b`, `--bpf-pin-root` (default `/sys/fs/bpf`), `--debug/-d`, `--mock-ebpf`. Log-level order: a valid `RUST_LOG` wins (`EnvFilter::try_from_default_env`), else `--debug` → `debug`, else `global.log_level`, else `info`.
- Subcommands: `reload` sends SIGHUP to the real-datapath PID published in `/run/honk-core.lock`; `mode <rule|global|direct>` rewrites `global.dial_mode` in the config file; `proxy <group> <node>` validates existence and prints but persists nothing; `delay <node> [--url HOST:PORT]` performs raw TCP timing rather than a proxied urltest. The latter three are local-only and do not talk to the running engine.

### `crates/honk-tool`

The `honk-tool` CLI toolbox (bin crate, diagnostics that don't belong in the engine binary). Deps are honk-config + honk-outbound + honk-core (`default-features = false`, so no axum/aya). Subcommands:

- `sub <url|file|-> [--target HOST:PORT] [--url TEST_URL] [--udp-check HOST[:PORT]] [--timeout SECS] [--concurrency N] [--limit N] [--ua UA] [--tls-implementation tls|utls] [--utls-imitate chrome_auto]` — fetch a subscription (or parse a share-link file/stdin URL) and probe TCP families, URLTest, and supported UDP paths. VMess and nodes whose `network` excludes UDP render UDP as `n/a`; eligible VLESS nodes probe the path selected from `udp_encoding`, multiplex, target port, and Vision policy. Output exposes only display name, fixed carrier/transport/path shape, and fixed result codes; credentials and raw errors are never rendered.
  UDP DNS targets default to the engine's `GlobalConfig::udp_check_dns` list; prefer the first literal, otherwise resolve the first hostname only for eligible UDP DNS probes. Resolution, dial, send, and receive share that probe's timeout; resolution failure/timeout affects only its DNS column, never aborts the command or substitutes another target. Unsupported UDP nodes do not resolve this target. QUIC uses the host and port from `--target`.
  VLESS `udp_encoding=auto` selects framing per target. A policy-denied DNS or QUIC target remains `n/a` and is skipped before hostname resolution; supported sibling columns continue. Xray UDP/443 rejection and Vision path validation use the canonical VLESS policy rather than a mode alias.
  Health and URLTest resolver hooks return fallible results. Typed packet refusal remains terminal through DNS initialization, outer route iteration, and name aggregation, and is neutral at health/Score consumers. Capacity is surfaced as a CLI error, not `n/a`; it never substitutes a default DNS target. Ordinary failures retain existing fallbacks.
  UDP DNS hostname targets use the shared async DNS resolver with the first numeric `/etc/resolv.conf` nameserver and optional `/etc/hosts`, not blocking NSS/search-suffix lookup or a public-resolver fallback; an unavailable resolver stays a DNS-column error. Literal targets skip resolver construction.
- `bpf show <conn-state|redirect-track|domain-routing|routing-handoff> [--ip IP] [--limit N]` and `bpf stats` — quick reads of the running engine's maps under `/sys/fs/bpf` (raw `bpf(2)`; no aya, no program load). `domain-routing` follows the active `ROUTING_POLICY_ROOT` descriptor's domain-map ID. `stats` prints overflow counters, the `CONN_STATE_OCCUPANCY` gauge, and non-zero per-outbound tx/rx counters.
- `diagnose [--api URL] [--pin-root PATH]` — one-shot read-only health check: engine process, `daens`/`dae0` presence, daens fwmark rule, pinned maps present, occupancy/overflow, clash API reachability. Exit summary `all checks passed` / `N issue(s) found`.
- `geosite list [FILTER] | show <category> [--attr ATTR] | find <domain>` and `geoip list [FILTER] | show <code> | lookup <ip>` — offline content search of geosite.dat/geoip.dat (one record per line, `--file PATH` overrides the default search). Without `--file`, honk-tool selects the first regular file from `$DAE_LOCATION_ASSET`, `/var/lib/honk`, legacy `/var/share/honk`, CWD, honk share directories, then dae asset locations; it does not load a config to discover a custom `global.data_dir`. Backed by the read-only scan API in `honk-core::routing` (`GeositeScan`/`GeoipScan`, including `@attr` decoding); `lookup` is longest-prefix. `--attr` uses the same key-presence predicate as routing's `category@attr` filter, so tool output and expansion agree.
- honk-tool is a **static musl binary** for gateway deployment: build with the `build-musl` zig env (`ZIGCC_TARGET=x86_64-linux-musl` + ci wrappers) and scp — a gnu build fails to exec on VyOS.
